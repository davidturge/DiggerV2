Digger Versus Technical Spec

1Scope of v1

  • v1 = World 1, complete: 8 levels (collection, escape, puzzle, chase types) ending in The Drill boss, plus the upgrade-card system and 3 difficulties.
  • Fully offline: local save only. No backend, accounts, ads, or IAP.
  • Platform: Android via Google Play, packaged with Capacitor.
  • Out of scope: multiplayer stack/netcode, monetization, worlds 2–5, leaderboards/cloud save.
Standing preference: game experience first, visual polish later — grey-box until fun. Art is production work, never a gate.

3Architecture

core/      pure deterministic simulation — imports NOTHING from other layers
render/    three.js; reads core state, consumes core events
input/     touch/keyboard → commands
audio/     consumes core events (production-time)
platform/  Capacitor glue (haptics, save, lifecycle)
  • Fixed timestep: core ticks at 30/sec; renderer draws at 60fps interpolating between the last two states, with clamped catch-up.
  • Commands in: input produces move(dir8) | shoot | useAbility queued into ticks. Touch never mutates state.
  • State + events out: renderer reads positions from state each frame and consumes one-shot events (sack-wobble-started, enemy-crushed…) for effects.
  • Determinism, same-device level: seeded RNG, no wall clock, fixed ticks — enough for replays, headless tests, and server-authoritative multiplayer later. Lockstep is permanently ruled out.
  • Movement: continuous fractional positions over a tile grid; dirt clears per tile; hard rock takes 2 dig-hits.
  • Module boundaries lint-enforced; the core runs headless in unit tests.

4Rendering & Look

"Soft Clay · Lit" — chosen from the live look prototype; performance rules from the Android WebView research.

  • Straight-on perspective camera (~35° fov), soft real lighting (MeshStandardMaterial, roughness ≈ .85), rounded tiles, 16 tiles across, camera follows the player. Provisional: re-judge once the first real Blender model exists; matcap is the performance fallback.
  • Day-one performance rules: InstancedMesh per tile type (O(1) dig updates); ≤3 dynamic lights, 1 shadow-caster max, blob shadows; devicePixelRatio capped 1.5–2; explicit WebGL context-loss handlers wired to app pause/resume; pooled instanced particles (200–500); frame-time quality ladder, never skipped rAF.
  • Target floor (2026): Helio G85/G99-class, Mali-G52/G57, 4GB RAM. Test the packaged APK via chrome://inspect.

5Controls

  • Landscape only. Fixed virtual joystick bottom-left; 8-way snap steering. Diagonal digging kept (the 1983 original was 4-way; this is a deliberate upgrade).
  • Auto-dig while moving; carried diamonds slow the digger per the design doc.
  • Button cluster bottom-right, 2–3 button ceiling: Shoot ~84dp + ability ~64dp + one reserved slot. Shoot wears a heat-gauge ring filling toward a red jam (deliberately not a cooldown); the ability button gets an opposite-direction cooldown sweep.
  • Respect Android gesture-navigation insets (runtime query; viewport-fit=cover). Left-hand mirroring: future config flag.

6Core Game Rules

Straight from the design doc §2, implemented as sim systems: dig & collect · gold sacks (undermine → wobble telegraph → fall → crush; break when falling ≥2 tiles; pushable) · heat-meter shooting (kills enemies; only slows/pushes players — matters for future 1v1) · cherry → 5s frenzy · the bank (undeposited diamonds at risk, weight slowdown) · two ground types.

  • Combo: kills within a 3s window chain; +0.5× score per kill, cap 3×. State lives in the sim; presentation in render.

7Enemies

  • Shared flow field: BFS from the player over the tunnel graph a few times per second — chase steps downhill, frenzy-flee steps uphill. One computation serves every slime.
  • No corner-cutting: diagonal moves only when both orthogonal neighbors are open; sacks block the graph.
  • Chase-accuracy knob: wrong-turn chance ~25% Easy / ~10% Medium / ~0% Hard.
  • Spawners: ramping trickle per spawn point (interval shrinks, capped), set in the level file. Sealed-off slimes wander, never camp.
  • One slime entity, typed by data: Basic / Nimble / Puffy (splits on crush) / Swarm (spawns grouped).

8The Drill — World 1 Boss

  • Special entity with its own system; the "enemies don't dig" rule stays intact everywhere else.
  • Greedy straight-line burrow toward the player — predictable on purpose: the fight is won by luring it under sacks. Its tunnels become normal tunnels.
  • 3 sack hits to win. Escalation per hit: faster, shorter telegraphs; cave-ins after hit 1 — ceiling chunks collapse on the player's tile, telegraphed by falling dust.
  • Re-arming sack alcoves keep the fight always winnable. Death restarts the boss level.

9Upgrade Cards (campaign only)

  • Modifiers layer: base stats from tuning.json; cards push {stat, op, value} entries; systems read effective stats through the stack; level end clears the list.
  • Registry: numeric cards are pure data; specials add a named code hook (onHit, onKill, autoFire).
  • Draw: seeded 3-card pick per bank level-up; rarity weights start at 70/25/5; taken one-shots excluded; no duplicates in a draw; no reroll.
  • v1 pool — all 15 doc cards: Fast Legs · Sharp Drill · Light Armor · Double Shot · Fast Cooling · Heavy Sack · Collection Radius · Double Diamond Value · Deep Pocket · Shield · Fast Respawn · Push Wave · Lightning · Super Magnet · King Midas.

10Levels, Tuning, Difficulty

One JSON file per level: an ASCII tile grid plus structured fields (type + params, spawners, star thresholds, par time). TS-typed schema, validated at load. Hand-authored for v1; the future random-challenge generator emits the same format.

"grid": [
  "DDDDDDDDDDDDDDDDDDDDDD",
  "DDD*DDDDDD DDDD*DDDDDD",
  "DDsDDG DDD DD*DDDDRRDD",   //  D dirt · R rock · ␣ tunnel
  "DDP        DDD DDDRRDD",   //  * diamond · G sack · B bank
  ...                         //  s spawner · P player start
]
  • tuning.json holds every game number. Layering: global defaults ← difficulty multipliers ← per-level overrides. Difficulty is data, not code.
  • Stars: 1★ finish · 2★ ≥80% diamonds · 3★ + beat par time. One star set per level across difficulties. No hard timers outside escape/chase types.

11Save System

One versioned JSON document in @capacitor/preferences ({version: 1, …} + load-time migrations). Persists per-level stars & best times, unlocks, selected character, difficulty, settings, tutorial-seen flags. Saves on level completion and settings change only; no mid-level saves — app kill restarts the level.

12Game Feel / Juice

  • One effects registry in render: sim event → {particles, shake, hitStopMs, haptic, sound}. Sound slots exist now; audio sourcing is the one open item.
  • Hit-stop ~80ms, big moments only (sack crushes, boss hits). Hit-stop and shake are render-only — the sim never pauses.
  • Haptic tiers light / medium / heavy via Capacitor; a "reduce effects" setting dampens shake and flashing.

13Asset Pipeline

  • Blender → .glb (Khronos exporter, "Actions" animation mode) with Meshopt compression; KTX2 deferred until profiling demands.
  • glTF only carries PBR — the clay look is applied in three.js at load by swapping materials (soft-lit standard; matcap fallback).
  • Hand-built deform-only armatures (avoid Rigify with glTF). Clips: ~6–9 per hero, 3–4 per slime, 8–12 boss.
  • Budgets: heroes 1,500–4,000 tris · slimes 200–800 · boss 3,000–8,000; vertex colors over textures where possible.
  • Learning path: Grant Abbitt's "Creating a Game Character: The Rogue" (free), then GameDev.tv low-poly characters (optional).

14Suggested Build Order

  1. Project scaffold — Vite + TS, module boundaries + lint rules, headless core test rig
  2. Grey-box core loop: dig, collect, bank, sacks, heat-shooting (prototypes are reference, not codebase)
  3. Controls layer on a real device
  4. Level loader + tuning.json; author level 1
  5. Enemies (flow field, spawners) → levels 2–7
  6. Juice registry + combo
  7. Upgrade cards
  8. The Drill + level 8
  9. Art pass (Blender assets replace grey boxes) + audio
  10. Capacitor packaging, device testing, Play Store internal track
